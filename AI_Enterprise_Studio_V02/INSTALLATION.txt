AI Enterprise Studio V0.3.0 — Vérification des productions

Mise à jour : arrêter le serveur, sauvegarder le dossier local (dont donnees et config.json), récupérer main après fusion, redémarrer. Migration additive: verification_results. Ne pas recopier une ancienne base.
Les tests CSV et JSON sont intégrés sans dépendances. NEXUS et SENTINEL peuvent utiliser test_file avec des assertions JSON déclaratives. Les preuves sont conservées avec empreinte SHA-256, version, auteur, mission, résultat et scénario. Pas de récompense XP supplémentaire ni de validation générale.

Sandbox HTML facultatif : désactivé par défaut. Seul le propriétaire peut l'activer dans config.json. Nécessite Docker Desktop/Engine Linux local en cours de fonctionnement (Windows: conteneurs Linux, pipe docker_engine; Linux: /var/run/docker.sock). Depuis AI_Enterprise_Studio_V02 :
    docker build -t aes-verifier:0.3.0 sandbox
Puis ajouter au config.json existant (sans écraser les autres paramètres) :
    "html_sandbox_enabled": true
Le moteur ne télécharge aucune image automatiquement. Le build initial télécharge une image publique et Playwright ; pas d'appel OpenAI/Brave, pas d'achat de service. Le sandbox n'accepte ni commandes ni scripts de test arbitraires : le scénario est une liste bornée d'actions navigateur. Exécution HTML uniquement dans un conteneur non privilégié sans réseau, sans montage de fichiers de l'hôte, racine en lecture seule, temps/RAM/processus limités. Aucun secret injecté. Docker n'est pas une garantie absolue contre une faille de l'hôte; n'activer que sur un moteur Docker à jour et avec des fichiers internes maîtrisés. L'activation ne donne pas aux agents le droit d'installer Docker ou d'exécuter des commandes sur l'hôte.
Si Docker/image est absent, le résultat est indisponible, jamais réussi. Mettre html_sandbox_enabled à false pour désactiver. Arrêter une mission n'interrompt pas instantanément un test déjà engagé ; durée bornée.
