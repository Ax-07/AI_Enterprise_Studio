V0.4.1 — Installer n8n local (une seule fois)

Pré-requis : instance n8n locale déjà disponible sur http://127.0.0.1:5678, non exposée à Internet ou au LAN. Ne pas modifier une instance existante sans sauvegarde. Si aucune instance locale : démarrer Docker Desktop puis, dans V02, exécuter docker compose -f n8n/compose.yaml up -d. Ce fichier crée une instance distincte avec un volume persistant et un port loopback; ne l'utilise pas si une instance occupe déjà le port 5678. Créer le compte propriétaire local lors de la première ouverture. Ne pas utiliser un tunnel. Ne pas utiliser n8n Cloud avec cette version.

1. Arrêter AES. Dans PowerShell, dans le dossier V02 : powershell -NoProfile -ExecutionPolicy Bypass -File .\Configurer_n8n.ps1
   Le script génère un jeton aléatoire (ou relit le jeton existant), protégé par DPAPI du compte Windows, et le copie dans le presse-papiers local. Ne jamais transmettre ce jeton. Le presse-papiers peut être lu par d'autres applications : désactiver historique/synchronisation et effacer après usage.
2. Dans n8n, importer aes_health.json et aes_metrics.json depuis ce dossier. Dans Webhook AES de chaque workflow, choisir Header Auth; créer UNE credential n8n Header Auth appelée AES Local (Name : X-AES-Token ; Value : coller). Réutiliser la credential pour les deux. Publier/activer les deux workflows. Vérifier le code et les paramètres avant publication. Aucun identifiant d'administration requis.
3. Effacer le presse-papiers et son historique. Démarrer AES via Demarrer_Enterprise.bat, qui relit le jeton DPAPI. Autres OS : fournir AES_N8N_TOKEN en variable d'environnement locale; aucune clé dans Git.
4. Outils & connexions : activer les deux capacités n8n, autoriser MIDAS et ORION par exemple, quota total 20 chacune. Tester chaque workflow. Un statut received avec ID exécution et résultat vérifié est attendu. Si unknown : vérifier que n8n est local, publié et Header Auth correct; ne pas répéter automatiquement. Exporter le journal sans secret.
5. Dans une campagne de recherche ciblée (exploration/market), autoriser un quota connecteurs >0; les agents voient uniquement les capacités permises. Aucune exécution commerciale. Les anciennes autorisations sont figées.

Contrats : n8n.health {} -> ready:true. n8n.metrics {values:[10,-3,7]} -> count:3,sum:14,min:-3,max:10. Pas de texte libre, données clients, URLs, fichiers ni code fourni par les agents. Les modèles ne voient jamais le jeton. Les workflows n8n livrés sont du code fixe et doivent rester inchangés. Les exécutions n8n peuvent contenir des headers dans les données internes; sauvegarde des données d'exécution désactivée dans les templates, vérifier les paramètres d'instance. HTTP boucle locale uniquement. Le jeton n'est pas un coffre-fort général; protéger le compte Windows et l'instance n8n. Aucun retry ni polling API d'administration. Une réponse inconnue ne signifie pas qu'aucun workflow n'a tourné.
